# Reflection — Lab 02

> เอกสารนี้เป็น Draft สำหรับนักศึกษา ปรับถ้อยคำและเพิ่มสิ่งที่เรียนรู้จริงได้ตามต้องการ

## สิ่งที่สร้างใน Lab นี้

ใน Lab 02 ผมพัฒนาเว็บแอปพลิเคชัน Flask สำหรับคำนวณ DC Operating Point ของวงจร BJT Common-Emitter แบบ Voltage-Divider Bias โดยรับค่า VCC, R1, R2, RC, RE, β และ VBE จากฟอร์ม แล้วให้ Python Backend คำนวณ VB, VE, VC, VCE, IC, IB และ IE พร้อมหน่วยกำกับ ผลลัพธ์ถูกส่งกลับมาแสดงในหน้าเว็บผ่าน Jinja Template

โปรเจกต์แยกความรับผิดชอบออกเป็นหลายไฟล์: `dc_bias.py` เก็บสมการทางวิศวกรรมล้วน ๆ, `app.py` ดูแล HTTP และการแปลงหน่วย, `templates/index.html` แสดงผล, `static/style.css` ดูแลหน้าตา และ `tests/` ตรวจสอบทั้งสมการและเส้นทาง HTTP

## ทำไมการเปิด `templates/index.html` ตรง ๆ จึงไม่เหมือนการรัน Flask

ไฟล์ `index.html` เป็นเพียง Template ที่มีช่องสำหรับเติมค่าจาก Python การ Double-click เปิดไฟล์จะทำให้เบราว์เซอร์แสดงข้อความ Template โดยไม่มี Server รับ Request และไม่มี Python คำนวณผลลัพธ์ การรัน Flask ทำให้เบราว์เซอร์ส่ง HTTP Request ไปยัง Server ซึ่งเรียกฟังก์ชันใน `dc_bias.py` แล้วนำผลลัพธ์มา Render เป็น HTML กลับไป

## ฟอร์มส่งข้อมูลไปยัง Python อย่างไร

เมื่อกดปุ่ม Calculate เบราว์เซอร์ส่ง HTTP POST ไปที่ `/calculate` พร้อมค่าจากช่อง Input ใน `request.form` จากนั้น `app.py` อ่านค่าเหล่านี้ แปลงข้อความเป็นตัวเลข ตรวจสอบความถูกต้อง แปลงหน่วยความต้านทานเป็น Ω และเรียก `calculate_dc_bias()` เพื่อคำนวณ

## ทำไมแก้สมการใน `dc_bias.py` แล้วไม่ต้องแก้ HTML

เพราะ Template ไม่ได้เก็บสมการทางวิศวกรรม มันเพียงแสดงค่าที่ `BiasResult` ส่งมาให้ หากสมการเปลี่ยนแต่ชื่อฟิลด์และความหมายของผลลัพธ์ยังเหมือนเดิม ก็แก้เฉพาะ `dc_bias.py` และ Tests ที่เกี่ยวข้องได้ โดยไม่ต้องแตะ HTML

## ทำไมผลนอก Active Region ต้องมี Warning

สมการที่ใช้เป็น Forward-Active Approximation ซึ่งสมมติว่า β คงที่, VBE คงที่ และรอยต่อ Base-Emitter อยู่ในสภาวะ Forward Bias ถ้า `VTH ≤ VBE` ทรานซิสเตอร์จะเข้าสู่ Cutoff และถ้า `VCE < 0.3 V` จะเข้าสู่ Saturation หรือใกล้ Saturation ในสภาวะเหล่านี้สมการ Forward-Active ไม่ได้อธิบายพฤติกรรมจริงได้อย่างแม่นยำ จึงต้องแสดง Warning และไม่ควรนำค่าที่ได้ไปใช้เป็น Operating Point ที่ตรวจสอบแล้วโดยไม่มีคำเตือน

## สิ่งที่ได้เรียนรู้

- การแยก Engineering Logic ออกจาก HTTP และ Presentation ทำให้ทดสอบได้ง่ายและแก้ไขได้ตรงจุด
- การใช้ Dataclass ช่วยให้ชื่อฟิลด์และหน่วยชัดเจน
- การแปลงหน่วย Ω/kΩ ต้องทำที่ขอบของระบบ และควรแสดงค่าที่แปลงแล้วเพื่อตรวจสอบย้อนกลับ
- Automated Tests ช่วยยืนยันทั้งสมการทางวิศวกรรมและพฤติกรรมของหน้าเว็บ
- การจัดการ Input ที่ผิดพลาดและการแจ้ง Warning เป็นส่วนหนึ่งของงานวิศวกรรม ไม่ใช่เพียงการตกแต่ง UI

## ข้อจำกัดและแนวทางต่อไป

แบบจำลองนี้เป็น DC Bias ภายใต้ Forward-Active Approximation เท่านั้น ยังไม่มี AC Small-Signal, Transient, Bode Plot, DC Load Line หรือ SPICE/ngspice การพัฒนาต่อในสัปดาห์ถัดไปสามารถเพิ่ม Bias Template อื่น ๆ แล้วค่อยยกระดับความสมจริงของ DC Analysis ตามลำดับของรายวิชา
